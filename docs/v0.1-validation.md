## Known V0.1 boundaries

- A hard crash after an immutable artifact blob is written but before its
  ownership event is appended can leave an unreferenced blob. It cannot affect
  projection or promotion; `verify` reports the store non-clean and V0.1 does
  not delete it automatically.
- A hard crash after Git unregisters a worktree but before validated filesystem
  fallback completes can leave an unregistered directory. A later process lacks
  the captured identity proof and must fail closed for operator review.
- Git subprocesses do not have a separate per-command timeout; they remain
  trusted local tools governed by the outer operation fence.
- The live failure-timeline correction has retained diagnostic evidence and
  static review but no dedicated nested harness-level automated regression.
- The whole `fwa/` tree is currently untracked in its containing Git worktree.
  This does not change runtime correctness, but it remains a delivery/preservation
  risk until the user explicitly chooses to stage and commit it.

The `.fwa` store and retained live directory are sensitive local engineering
evidence. Hashes provide integrity, not confidentiality: logs and artifacts can
contain absolute paths, model output, command output, Unity licensing details,
patches, and NUnit XML. They should not be committed or published without
review and redaction.
