# FWA 可视化工作台

本页描述当前可选 FWE 工作台，不改写最初 CLI-first V0.1 的冻结验收范围。
本轮已接通资料副本导入、真实 Codex 规划、层级与依赖展示、隔离并行 Work、
显式反馈修订及执行/验收产物浏览。受信配置可接通候选验证、人工或策略确认、采用、
撤销与有无对照。自动采用遵守启动策略，人工判断合同仍需确认；资料可写回写和游戏
视觉采集仍未完成。界面不代表游戏已验收，当前交互规则见[节点工作台](node-workbench.md)。

## 启动与操作范围

项目先通过 `fwa init` 初始化，再从包含同级组件的目录启动：

```powershell
node fwa/bin/fwa.js editor --project D:/Games/MyGame --fwe-path D:/Git/fw/fwe
# 允许受控导入、规划、Work 和修订；必要时选择已安装的原生 Codex：
node fwa/bin/fwa.js editor --project D:/Games/MyGame --fwe-path D:/Git/fw/fwe --allow-write --codex-path D:/Tools/Codex/codex.exe
```

默认只读，监听 `127.0.0.1:3220`。FWE 必须包含 guarded server contract v1
和 `fwe.ui.createGraph`；启动不克隆、不更新组件，不初始化或修复宿主。
详细安全边界见 [README](../README.md#optional-fwe-control-console)。

`--codex-path` 是启动者选择的现有、绝对原生程序路径；Windows 要求 `.exe`，拒绝
`.cmd`/`.bat`。不传仍使用原解析器，不安装程序、不跳过用户配置、不改变沙箱边界。
已有宿主启动器的 `codexPath` 配置方式见 [交互合同](interactive-workflow.md#启动配置)。

`--allow-write` 开放资料导入/权限、Plan/Work、节点反馈、显式计划修订，以及保留的
创建目标、手工计划 JSON 和节点重试 API。当前页面不再提供独立的手工命令表单。
底层重试 API 仍只是重新排队，不立即启动执行器，
也不重置预算。配置 `--review-config` 后，Work 自动验证候选并在同一次请求中续修
普通执行或验证失败。`completionPolicy` 允许的合同通过检查及集成回归后自动采用；
其他合同显示“确认并继续”。只有真实采用才解锁后继。进程崩溃后的核对与恢复仍使用
CLI/API。具体合同见 [change-review.md](change-review.md)。

没有文件改动的候选保留在 `no-changes-awaiting-review`，不会自动采用；配置好的机器
验证仍可检查同批独立的非空候选。零改动可能是合法无操作，也可能是工具受阻，需要核对执行日志；不凭
模型退出码或自然语言猜测成功。旧作业记录不改写，界面按它绑定的 ChangeSet 补充警告。

## 分区与事实含义

默认入口是需求、持久任务图与所选节点详情组成的单页工作台。已有任务时“新建任务”
收起，顶部“继续”推进当前目标；执行记录、差异、证据与对象链接按需展开。下表描述
可检查的事实类型，不代表存在对应阶段导航或全部默认展开。

| 分区 | 当前能力 | 不能据此推断 |
| --- | --- | --- |
| 资料与需求 | 文件/目录/ZIP 副本导入、版本目录树、继承权限、受支持内容预览；可选文字与资料经真实 Codex 生成计划，歧义返回问题；查看持久作业结果 | 上传不修改原目录；作业返回不是需求完成；支持预览不等于模型已理解视频、音频或 PDF |
| 层级与任务 DAG | 成果与前置理由、目标筛选、搜索、缩放平移和关联高亮；分组汇总真实完成情况；Work 调度叶子 | 父组不是可执行 Node；图中位置不是执行顺序；阻断/失败标记不篡改执行状态；后继需要实际集成结果 |
| 引用与材料 | 注册 Ref 的对象链接、文本/图片/SVG 预览，以及记录中的 Node 与 Ref 声明关系 | 声明读取/写入不是实际文件访问，也不是 implemented-by、verified-by 等语义知识图 |
| 执行历史 | 同一 Node 的多次 Run、执行器、时间、工作区、基线、失败、关联变更和声明输入版本 | `produced` 只代表产出阶段完成，不等于任务完成、验收通过或已集成 |
| 变更审查 | 节点内显示结果及确认入口，差异按需读取；自动验证、策略或人工确认、回归后采用；撤销与有无对照按需展开 | 需受信项目检查；零文件变更不是成功；检查通过不替代视觉判读 |
| 验收证据 | 验收项结果、耗时、stdout/stderr，以及验证版本与不可变文本/图片/视频产物 | 媒体字节可读不证明它是真实游戏画面或正确的 before/after；编译通过不等于功能/视觉验收通过 |
| 事件 API | 项目全局持久化事件，CLI/API 按序号分页读取原始载荷与因果标识 | 不是模型 token 直播；单页工作台已移除旧事件分区 |
| 项目与安全 | Goal、集成/回退历史、Git fence 和 workspace lease 快照 | 没有占用不等于完整 `fwa verify`；查看不会恢复或清除阻断 |
| 目标与计划 | 手工 CLI/API 保留；页面节点反馈持久化，通过显式模型重规划或 authored plan 修订产生新版本，保留旧结果与历史 | 提交反馈不立即应用；修订不自动继续 Work；手工计划、普通工作区 Ref 更新、暂停/恢复、审批没有独立网页表单 |

Node 的执行状态、有效性和集成状态必须一起阅读。例如：

- `planned` 节点可以因前置被拒绝而显示阻断，但仍保持 `planned`；
- `accepted + stale` 表示旧结果曾通过验收，但已不再对应当前输入；
- `produced`、`accepted`、`integrated` 不是同义词；Run 失败记录与后续尝试都保留。

另外的 `plan/ready/work/done` 是同一事实链的递归汇总：全部子项 done 才 done；
已有子项开始但未全部完成为 work；未开工而有 ready 子项为 ready，否则为 plan。
叶子 done 必须是当前、有效、已验收且已集成到 Goal 目标的结果；失败、暂停、
待反馈等标记独立显示，不能用四阶段替代 Node 的执行/有效性/集成三维状态。

图是只读投影。拖动画布、缩放、点击和搜索不会保存布局到 FWA 事件，也不会增删
依赖。画布支持滚轮缩放、空白处拖动平移、方向键选择、`+`/`-` 缩放、`0` 适应画布
和 `Escape` 清除选择；分区工具栏也提供适应画布。

## 输入内容与证据不是同一种来源

资料库导入保存原始文件副本、目录树、不可变版本和摘要，不写回拖入的原位置。
单文件上限 16 MiB、一次导入总量 32 MiB、最多 2000 个条目；只有 ZIP 支持解包，
不宣称支持 RAR/7z 等。拖入目录可保留空目录，系统文件夹选择器可能不返回空目录。
规划选择的是资料库当前版本；切换历史版本预览不会改变规划选中的版本。

路径权限默认只读，子项可覆盖父项。`deny` 在内容 API 和输入快照筛选中实际生效；
`read/write` 标记不是操作系统 ACL 或敌对执行器沙箱。当前 Work 将输入快照统一
作为只读任务数据，“允许修改副本”尚未接通模型修改、验证和写回新版本的流程。
改权限不会撤回已发给正在运行尝试的输入，也不授权原目录、工程或框架写入。

资料库中的图片、视频、音频可交给浏览器预览，PDF 可打开副本链接。当前 Planner
输入只明确提供受限文本摘录和最多 16 张受支持图片；其他格式保留副本及元数据，
不据此声称模型已读懂内容。库版本描述不冒充普通物理工作区 Ref。

Ref 详情展示当前工作区文件，并标注注册版本与摘要比较。这不是当次 Run 的历史
文件快照。Run 中的 `effects` 是当次声明绑定的版本；注册 hash 还可能采用集成版本
协议，不能一概当成当前文件内容摘要。图片详情的 URL 绑定读取 metadata 时观测到的
SHA-256，文件在两次请求间改变会使图片请求失败，不会悄悄换成另一版本。

文本按安全的简化文档样式显示，不执行 HTML/脚本。只预览已注册、受支持类型的
单个普通文件；glob 不扫描目录，越界路径、symlink/junction 和不支持的文件明确拒绝。
当前文本上限 2 MiB，图片上限 8 MiB。

patch、执行日志和验收日志来自项目事件中的完整 artifact 引用，或经大小与 SHA-256
验证的 JSON 产物内可达引用。不能输入任意磁盘路径或只凭猜测 digest 读取文件。
单个 artifact 上限 8 MiB，文本展示最多 2 MiB 并注明截断；关联查询还受 256 个产物与
32 MiB 总读取预算限制。缺失、损坏、不支持或超限是读取失败，不会自动修复。
已识别的 PNG/JPEG/GIF/WebP 与 MP4/WebM artifact 可以浏览，仍受上述大小、可达性
和摘要约束。AI 概念图可以是输入材料；控制台录像只证明控制台交互。只有真实游戏
运行捕获、正确的前后版本绑定与验收记录才能作为游戏视觉证据。默认流程尚无自动
游戏启动/截图/录像、before/after 配对和视觉判定，Planner 提示不能替代这些实现。

## Work 与反馈修订的停止边界

Work 通过 `runReadyBatch` 为最多四个 ready 叶子创建独立工作树，由一个批次协调器
持有真实 lease。读写范围或独占资源有冲突的叶子会延后；并行不是让所有任务无条件
同时启动。各 Run/ChangeSet 独立留存。受信 review 配置提供验证与采用能力，普通失败
按预算续修，重复无进展或恢复状态不明确时停止；依赖这些结果的下游不会仅因
`produced` 而继续。

反馈提交后保持 pending 并阻断该 Goal 后续派发。已派发的运行先收束，输入不被替换；
操作者再明确请求修订。修订保留逻辑 ID，为受影响叶子创建新物理版本并传播到依赖/声明
Ref 消费者，历史 Run、commit、Evidence 不被覆盖；无关分支保留。被退休节点的全部
pending 反馈必须明确纳入，不能自动视为已处理。未尝试成果可以在保留验收义务与
消费者的前提下派生为少量不同成果；已尝试成果保持逻辑身份和预算。命名验收合同
不能由模型拆分。修订成功后仍需明确启动 Work。

## 刷新、草稿与幂等提交

可见页面每五秒检查状态，也可手动刷新。失败时醒目标注为上次快照并关闭提交能力；
没有新增事件或占用变化时，不重建内容区。图形选择与手动缩放平移在后台图更新时保留。

表单草稿保存在当前页面内，切换对象后仍可恢复，刷新整个网页则不会保留草稿。
同一种命令正在提交时，对应字段和提交按钮锁定，后台刷新不会解锁。未确认命令的
ID 单独按项目、命令类型及 payload 保存在 `sessionStorage`：内容不变的重试复用 ID，
收到成功确认才删除。跨页面重载时需重新填入同样内容，不能把 ID 日志误认为草稿持久化。
关闭标签页或清除存储后，应先检查 CLI 事件再重复不确定的操作。

## 浏览器验收清单

`tools/check-workbench-browser.mjs` 可用已安装的 Chrome 与 Playwright 对真实项目
执行只读浏览器回归并输出截图。传入 `--project`、`--fwe`、`--browser`、
`--playwright` 和 `--output` 的绝对路径；它不会安装依赖或提交表单，结束时核对
项目状态与运行前一致。当前场景针对单个目标、包含任务和引用材料的工作区，
输出 `summary.json` 记录实际执行的检查；跳过的材料类型不会被算作通过。

`tools/check-workbench-fixture.mjs` 使用 `--fwe`、`--browser`、`--playwright` 和 `--output`
四个绝对路径参数，在临时 Git 工程中生成真实非空补丁并执行命令验收，检查分叉汇合图、
Run/ChangeSet/Evidence 联动与多页事件追加。它不运行 LLM，也不修改实际游戏工程；
完成后关闭浏览器/服务并清理自己创建的临时工程，截图与结果留在指定输出目录。

`tools/check-interactive-workflow.mjs` 使用同样四个参数，在临时工程中经真实浏览器操作
导入、权限、Plan、Work、反馈和修订，连接真实 FWE/API/Git；Planner/Executor 是明确
标识的确定性测试适配器，因此它不是实际 LLM 或游戏验收。`tools/check-workflow-planner.mjs`
则单独调用真实 Codex，使用自动生成的非个人规划 brief，只验证计划生成、零 Run 和
工程未改动。调用形式为 `node tools/check-workflow-planner.mjs <输出目录> [原生Codex路径]`；
它保留临时工程与原始执行证据，不属于 `npm test`，会实际使用模型服务。

这里不宣称已全量通过。focused、live-planner 和
browser 报告必须分别核对真实输出、失败、跳过及源代码版本，不能互相替代。

以下是人工/浏览器验收要求，不是本文件宣称已经执行的结果。自动投影、命令日志和
真实 HTTP 测试分别位于 `test/editor-workbench-model.test.js`、
`test/editor-command-journal.test.js` 与 `test/editor-queries.test.js`；异步内容生命周期
回归位于 `test/editor-content-lifecycle.test.js`。图组件测试属于
同级 FWE。测试通过不替代真实输入、布局与交互验收。
新增合同回归还包括 `test/reference-library.test.js`、`test/workflow-revisions.test.js`、
`test/run-batch.test.js`、`test/workbench-controller.test.js`、`test/editor-workflow.test.js`
和 `test/workflow-panel.test.js`。

- 用分叉后汇合的 DAG 检查每条真实依赖、选择高亮、缩放平移、键盘操作和目标筛选；
  不产生悬空边，不将下游阻断涂改成其执行状态。
- 导入目录/ZIP，核对原件未改、目录与版本、父级权限和子级覆盖；拒绝内容不进入新输入
  快照，不把“可写副本”测试成已实现回写或 OS 隔离。
- Plan 不产生 Run；Work 的不同叶子确实使用不同工作树，冲突叶子不执行，按配置验证
  并自动采用或等待人工确认。运行中反馈只留 pending；显式修订保留历史，无关分支不重算。
- 同一 Node 保留至少两次 Run；失败尝试、零文件产出、拒绝 Evidence、未集成都可区分；
  检查 ChangeSet、Run、Evidence 的绑定，不能混用另一次尝试的日志。
- 打开真实 Markdown、图片和 SVG Ref，再连续快速切换两项；旧请求晚到/失败时不污染
  新详情。图片内容变动后不能在旧 metadata 下显示新 bytes。
- 从 ChangeSet 查看真实 patch，从验收项查看 stdout/stderr，从执行产物查看失败正文；
  空、超限、损坏或不支持的产物不显示为成功。
- 通过事件 API 读取超过一页的事件，核对追加后的序号与游标，原记录不可改写；
  旧事件分区已退场，其独立 renderer 的生命周期由针对性测试覆盖。
- 填写草稿后等待后台更新并切换对象；提交未完成时刷新、再展开表单，不得重复提交或
  解锁同类型命令。模拟丢失响应后，以原 payload 重试并核对只追加一次事件。
- 只读模式无命令能力；越界/glob/链接文件和未授权 artifact 读取被拒绝；运行中源码
  变化使服务拒绝继续使用，而不是热替换。浏览事实不恢复 lease/fence 或清理工作区。

## 后续业务边界

当前仍缺普通工作区 Ref 注册/更新与
影响预览、资料可写副本的执行回写、暂停/取消/恢复、审批，以及自动运行时截图/视频/
遥测验收。自动持续吸收反馈并继续执行也不同于当前“显式触发模型修订”。语义 Ref
知识关系、学习与多引擎完整适配仍是后续工作。规划、并行和计划修订已经实现，不能再
引用历史 V0.1 的排除项说它们全部不存在，也不能据此宣称用户完整工作流已交付。
